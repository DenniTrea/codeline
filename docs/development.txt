with an eight-hour lifetime and a stable SESSION_SECRET. That folder is private

MSAL token result. Keep it on persistent VM storage if deploying.
For production set NODE_ENV=production, a strong stable SESSION_SECRET,
FRONTEND_ORIGIN=https://your-host, MICROSOFT_REDIRECT_URI=https://your-host/auth/callback,

EXERCISE AND LIVE GAME MILESTONE — 25 November 2026
The existing schema was inspected again; no migrations, new tables or database
resets were run. The following supersedes earlier notes that these flows were
unimplemented.

EXERCISES
New exercise -> Blank / Copy an exercise / Import file -> ordered code editor ->
Save draft / Save ready. Metadata includes course, topic, problem, pseudocode,
duration and wrong-attempt penalty. Admin/staff can add topic names explicitly.
Code import is inert text, preserves indentation, normalizes CRLF and marks empty
formatting rows GIVEN. Limits: 128 KB import, 500 lines, 2000 characters per line.
Ready exercises need a problem and at least one nonempty BLANK answer. Course
planned count is only a guide; lobby creation uses the actual enrolled roster.
Copying generates independent line IDs and preserves copiedFromId. Once any game
references an exercise it cannot be edited; copy it instead. Delete archives it,
preserves games, and offers Undo. Failed initial loads disable mutation controls
and offer Retry. Unsaved editor navigation is confirmed before discarding work.

GAMES
Creating a lobby snapshots courseStudents into gameParticipants and reserves a
unique six-digit PIN. The number of BLANK lines must equal the enrolled roster;
GIVEN lines are extra. Staff can lock a lobby, correct attendance, or close an
unstarted lobby. Started games are retained. Students can enter the PIN, rejoin,
or explicitly leave an unstarted lobby; disconnecting does not reset assignment.
At start waiting students become absent. BLANK lines are shuffled and assigned
uniquely. Absence reveals the assigned answer for 0 points. Backend placement
checks are authoritative: 100 initial points, subtract the exercise penalty for
wrong placement, floor 0. Correct placement retains remaining points. All joined
students solving ends the game; manual end or deadline gives unsolved students 0.
The user explicitly confirmed unsolved=0 on 25 November.

Game state is derived from timestamps. The server closes expired sessions on a
one-second sweep and on game reads; deadlines survive an API restart. Scores and
assignments are in PostgreSQL. Student payloads omit assigned line IDs/positions,
hidden code and staff rosters. Only visible board lines and the student's own
code are returned. Game queries and mutations are enrollment/host/role checked.
Line assignments, starts and scoring serialize on the game row. Repeated request
IDs deduplicate attempts in memory for ten minutes; this is not a durable audit
or an exactly-once guarantee across API restarts. Mutations are never retried
automatically after network failure.

Socket.IO shares the authenticated cookie session and rechecks roles/room access
when subscribing. It broadcasts room-change notifications; clients read their
own authorized state. Same-origin polling and WebSockets are supported, with a
5-second HTTP refresh fallback. Foreign origins, anonymous sockets, unauthorized
rooms and malformed packets are rejected. Cosmetic movement is bounded and
batched per room; colors and four predefined emotes are temporary, with no free
text chat. WASD/arrows, clicking the floor and mobile movement buttons work.
The waiting-room layout follows Figma frame 150:5854 using native pixel shapes.

RESULTS AND RETENTION
Students see their score, rank, elapsed solve time and revealed code. Staff see
this-game/course-total leaderboards, CSV export, temporary activity and Play again.
Results/history reference the original immutable exercise. Course totals use
finished games, matching the simplified course schema: no invented sections or
semesters. Detailed activity is limited to the latest 2000 entries per game for
this server session and can be exported separately. It is not a persisted history
log. No submissionAttempts, attemptCount, semester or section tables were added.
CSV protects against formula injection and preserves Unicode/numeric penalties.
Pause/time extensions and a permanent attempt audit were not added; those would
need separate state/retention decisions. No submitted code is executed.
